# Jev 僚机主界面重构设计

## 目标

把当前的开发调试面板改成一个面向日常使用的运行控制台。用户打开应用后，应能在几秒内知道是否可以使用、完成缺失权限、启动或停止悬浮球，并查看最近一次判定；端点、模型和原始诊断信息仍然保留，但不占据首页。

本轮只重构 Android 原生主界面及其交互层级，不改变无障碍抓取、远端请求、本地模型和悬浮球行为。

## 当前问题

- `activity_main.xml` 把端点、模型、API Key、上下文行数、测试、三种演示、抓取、模式切换、模型自检、权限和悬浮球控制全部纵向平铺。
- 状态文本同时承担运行状态、模型状态、最近抓取内容和诊断输出，无法快速扫描。
- 权限缺失没有紧邻的修复动作，用户需要自己理解“无障碍”和“悬浮窗”的关系。
- 当前没有判定历史存储，直接增加趋势图会产生没有数据依据的视觉信息。

## 页面结构

主页面仍是一张可滚动页面，使用四个主要区域：

1. **顶部品牌区**
   - 新版 J 双翼图标、`Jev 僚机` 标题和一句短说明。
   - 右侧显示状态徽章：`可使用`、`需要设置`、`运行中`。

2. **运行控制卡**
   - 主标题根据状态显示“悬浮球已停止”或“悬浮球运行中”。
   - 一个高对比主按钮负责启动/停止；启动前若缺权限，按钮变为“完成设置”，并滚动到第一个缺失项。
   - 下方两行权限检查：无障碍服务、悬浮窗权限。每行显示状态、解释和就地修复按钮。
   - 判定模式使用二选一切换：`远端 Jev` / `本地模型`，当前模式有明确选中态。

3. **最近判定卡**
   - 显示最近一次判定的来源窗口、相对时间、结论摘要、耗时和判定模式。
   - 无历史时显示空状态：“还没有判定，去聊天窗口点悬浮球试一次”。
   - “查看抓取内容”是次级操作，展开后显示统计和截断后的原始文本；长文本必须限制高度并可继续查看。

4. **更多操作区**
   - “试用演示”作为一个入口，进入后选择私聊（有情绪）、私聊（日常）或群聊。
   - “高级设置”折叠端点、模型名、API Key 和上下文行数，保存按钮放在该区底部。
   - “开发诊断”折叠测试判定、本地模型自检、现场抓取和诊断输出。

## 状态与交互

页面状态由现有 `Prefs`、权限检查、`OverlayService.running`、最近抓取快照和最近判定结果组合得到，不增加第二套真相来源。

- **首次打开**：显示“需要设置”，运行控制卡展开权限检查，其他卡片收起。
- **权限不全**：主按钮显示“完成设置”，点击后定位到第一个缺失权限；各权限行仍可单独打开系统设置。
- **权限齐全但悬浮球停止**：主按钮显示“启动悬浮球”，模式切换可用。
- **运行中**：主按钮显示“停止悬浮球”，顶部状态徽章变为“运行中”。
- **判定进行中**：最近判定卡显示加载状态和取消/失效后的明确提示，避免旧结果看起来仍然有效。
- **操作成功或失败**：在操作卡内显示短时状态提示；错误文案必须包含下一步动作，例如“API Key 无效，请到高级设置重新保存”。

页面返回前保留折叠状态和滚动位置，不清空用户正在编辑的字段。API Key 继续遵守现有策略：空输入不覆盖已保存密钥。

## 视觉系统

- 背景使用浅冷灰，主卡片使用白色或极浅蓝，主色沿用新版图标的深蓝，强调色使用青绿色。
- 主按钮和状态徽章使用明确的语义颜色，但不只依赖颜色：同时显示文字和图标/状态词。
- 卡片统一圆角、内边距和分组间距；删除当前大量相同宽度按钮造成的“控制台列表感”。
- 标题、说明、辅助数据分出三级字号；耗时和数量使用等宽数字或稳定的数字宽度。
- 所有可点击区域至少保持适合触摸的高度，输入框有可见标签和明确的提示文字。

## 数据与图表边界

本轮不增加图表。后续若需要“判定趋势”，先新增轻量本地历史记录，保存最近 20 次的时间、模式、风险等级、结论和耗时；图表只基于这些真实记录，优先展示：

- 风险等级分布；
- 最近判定耗时的迷你折线；
- 本地/远端使用比例。

历史记录需要有清空入口和容量上限，不能保存完整聊天文本或 API Key。

## 预计改动范围

- `app/res/layout/activity_main.xml`：重排主页面，增加卡片、权限行、模式切换和折叠区。
- `app/src/ai/jev/assist/MainActivity.java`：把现有按钮监听映射到新控件，集中刷新状态卡和折叠区内容。
- `app/res/values/strings.xml`：补充状态、错误和空状态文案。
- `app/res/values/styles.xml` 与 `app/res/drawable/*`：建立主色、卡片、状态徽章、分段切换和按钮样式。
- 如有必要新增轻量自定义 View，仅用于折叠状态或趋势图占位，不引入大型 UI 框架。
- `DemoActivity` 的三个演示页面保留行为，只把入口合并为单一演示入口。

## 可访问性与验证

- 每个输入框都有对应可见标签；按钮文字描述具体动作，不使用只有图标的无标签按钮。
- 状态变化使用可读文本同步更新，焦点不会因为折叠或异步结果跳到无关控件。
- 通过无障碍服务检查、悬浮窗权限检查、远端/本地模式切换、空状态、错误状态和小屏滚动测试。
- 在真机上验证深色/浅色系统主题下的对比度、状态栏安全区、键盘弹出后的滚动和旋转恢复。
- 现有模型、抓取、远端请求和悬浮球回归测试必须继续通过。

## 不在本轮范围内

- 不改变判定问题、模型输入、抓取逻辑或远端 API 协议。
- 不新增账号系统、云端历史同步或复杂图表库。
- 不把完整聊天记录写入历史数据。
