# Jev 行为说明

这份文档记录 Jev 僚机在聊天场景中的可验证结论，帮助使用者理解它能做什么、不能做什么。

## 上下文比单句更重要

判定使用最近若干行对话。只读最后一句时，意图和情绪可能被高置信度地判断错；补充前文后，结论通常更稳定。应用默认保留一段上下文，读到的行数太少时会明确提示“判定不可靠”。

不要只看百分比。先确认“最近判定”中的来源、行数和抓取内容，再判断结论是否值得参考。

## 群聊需要发言人信息

群聊成员通常位于同一侧，单纯按左右位置会把所有人都归为“对方”。应用会优先从无障碍节点中识别昵称，把消息写成“昵称：正文”；识别不到时才回退到左右分栏。

昵称识别不能解决所有语义问题。多人争执、引用消息、图片消息和自绘气泡仍可能让输入不完整。

## 读取方式是 Android Accessibility

应用递归读取当前窗口的无障碍节点，不截屏、不使用 OCR、不申请相机权限。这样速度快、不会产生 OCR 字符错误，但完全依赖聊天 App 是否暴露文字。微信等全自绘界面可能只暴露空节点，这是输入不可用，不是模型判定失败。

## 本地和远端的差异

本地模式使用量化中文句向量模型做近似判定，优点是离线和隐私；远端模式调用配置的 Jev 兼容端点，通常有更好的复杂语境表现，但需要网络和 API Key。两种模式输出相同的五类判断，不共享模型权重。

## 悬浮球状态

悬浮球只读取当前窗口，不发送消息。离开被判定的聊天窗口时，结果会失效并回到中性状态；迟到的网络结果不会重新覆盖新窗口。

首页“最近判定”只显示与当前抓取文本匹配的结果，抓取内容变更后不会继续显示旧结论。

## 不应如何使用

- 不要把判定当成事实或心理诊断。
- 不要在上下文不足时只看置信度。
- 不要把本地模型当作官方 Jev 的精度复刻。
- 不要在未确认远端服务隐私策略前发送真实聊天内容。
